ARMBench · Amazon warehouse picks · CPU pilot

Can a world model tell when a robot pick goes wrong?

A test harness that watches Amazon's robot-arm videos frame by frame and raises an alarm when a pick damages the item. It scores several "monitors" against the same rules, including Meta's V-JEPA2 world model. Below: what the data looks like, how the harness works, and what a first pilot run found.

Early results from a CPU pilot on 16% of the dataset (November 2026). Code: github.com/ghanemja/anomaly.

The data

What a failure looks like

Each clip is about 4.5 seconds of a robot moving one item from a yellow tote to a bin. Most picks are fine. In about 4% the packaging opens, or the item comes apart. Amazon labelled the exact frame where that starts (outlined in yellow).

Frames are from the 320 px copies used in the pilot. ARMBench, CC BY 4.0, Amazon Robotics.

How it works

A harness that scores every frame, not every clip

Amazon's own baseline looks at a whole clip afterwards and says "defect or not". A monitor running on a live robot has to decide as the video arrives. So every monitor here gives a score per frame, using only frames it has already seen, and an alarm fires the first time the score crosses a line.

StreamPull chosen videos out of the 254 GB archive without downloading it all.armwm/stream.py
LabelClean the labels: per-frame onset, splits, and the dataset's known quirks.armwm/labels.py
WatchEach monitor scores every frame from the past only. Five run on CPU; V-JEPA2 needs a GPU at scale.armwm/scorers, worldmodels
Set the alarmPick the threshold on normal clips the test never sees, so that 5% of normal clips alarm.armwm/metrics.py
ScoreOn Amazon's official test split: did it alarm, and how long after the damage started?scripts/run_*.py

One catch along the way. Hugging Face's V-JEPA2 code lets the model see the future frames before it "predicts" them. This monitor feeds it the past frames on their own, so its prediction is honest.

Monitors at work

How three monitors react to the same clips

Each line is a monitor's score divided by its own alarm line, so 1.0 means "alarm". The yellow band marks where the damage starts. A good monitor stays under 1 before the band and jumps over it after.

Latent predictor: a small world model trained only on normal clips; this line is its uncertainty. Nearest-normal distance: how unlike any normal frame this frame looks. V-JEPA2: Meta's pretrained world model, worst-patch prediction error (CPU run, coarser time steps).

Results · 1,857 test clips, 217 defects

Every monitor is weak so far

Clip AUROC is the chance that a random defect clip scores higher than a random normal one: 0.5 is a coin flip, 1.0 is perfect. The second chart shows how many defects each monitor catches when 5% of normal clips are allowed to alarm.

Show the numbers as a table

No labels, nearly as good as labels. The latent predictor never saw a defect, yet it ties the supervised model on clip AUROC (0.68 vs 0.69). Online, the supervised model still catches about twice as many.

Opened packaging is the hard case. Every monitor is near a coin flip on it. Items coming apart are easier.

No real early warning. Alarms before the damage starts happen at about the false-alarm rate, so they're luck.

V-JEPA2 is untested. It ran on only 30 clips on CPU, so its interval covers a coin flip. The real test needs a GPU.

Next

What a GPU run would answer

  1. Run V-JEPA2 on all 11,251 test clips at full resolution. Does a big pretrained world model beat the small one?
  2. Fine-tune its predictor on normal clips only. Recent work (CureWM) says off-the-shelf world models "dream of success" and miss failures; this tests it on real warehouse data.
  3. Add NVIDIA's Cosmos as a second world model, and port Amazon's MViT-B baseline for comparison.
